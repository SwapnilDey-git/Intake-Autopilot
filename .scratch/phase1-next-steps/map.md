Instrumentation was temporary and reverted (ai-service code unchanged).
- [Automated completeness check](issues/21-automated-completeness-check.md) — **built 2026-07-23.** Turned the human-only "is this complete?" judgment into an automated pass/fail over a mandatory-field set. Grill surfaced the core trap: a blank money field is ambiguous (real zero vs. omission) and extraction can't resolve it. Mandatory (7): `tax_year, e_card_number, name, is_signed, honorare, svs_sva, wko_contribution`; `provision_travel` deliberately optional (often legitimately zero → would false-flag every no-travel form). Ships as a configurable constant so the client's real must-have list swaps in one line. Warning-only badge (never hard-blocks approval); recomputes on the reviewer's current values at review time and logs an `audit_log` `'completeness'` event (captures whether an incomplete form was knowingly approved). Backend `evaluate_completeness()` + `/pending` payload + dashboard green/red badge (live-recomputed as the reviewer edits). Removes one of ticket 22's three blockers.
